# Major Project Student Checklist

## Before AI

- [ ] Submit the designated Edition A PDF through Brightspace and save the first successful
  receipt. Do not overwrite it. A Git tag is optional corroboration, not the baseline.
- [ ] Confirm the decision, intended user, evidence, assumptions, unknowns, and validation plan.

## Final frozen package

- [ ] `Research-Evolution.pdf`: unchanged Edition A, any dated correction addendum, Edition B,
  and A-to-B/no-material-change evidence table.
- [ ] Accessible repository: README, dependency/environment file, runnable source, visible
  executed output, `.env.example` when needed, and content-equivalent `docs/` records.
- [ ] If using the common project starter, copy `visible_output.example.json` to the project
  output path only after replacing every placeholder with validated results; the distributed
  `analysis.py` is intentionally unfinished.
- [ ] `Decision-Memo.pdf` (maximum two pages) or `Decision-Deck.pdf` (maximum eight main slides;
  concise sources/technical appendix permitted).
- [ ] `Validation-and-AI-Use.pdf`: sources/as-of boundary, tests, results, limitations, named
  material AI uses/dispositions with the exposed tool/model/version and interaction date, and the
  complete **Locked Changed-Input Record** (human-authored AI-off prediction before the run;
  immutable commit/snapshot; old and new values with units; expected and actual direction;
  decision effect; failure diagnosis when expectation and result diverge).
- [ ] Video 1 ≤3:00 plus `transcript-video-1.txt`.
- [ ] Video 2 ≤5:00 plus `transcript-video-2.txt`.
- [ ] Video 3 ≤5:00 plus `transcript-video-3.txt`.
- [ ] Brightspace manifest: stable repository/video URLs, optional deployment, titles/durations,
  timestamp indices, access confirmation, and frozen-file checklist.

## Cold check before submission

- [ ] A clean user can follow the README; record first failure and resolution/limitation.
- [ ] Instructional team can access private repository and every unlisted video logged out.
- [ ] Visible output shows material inputs, as-of date, and decision without running code.
- [ ] Captions/transcripts correct substantive finance terms, tickers, names, attribution, and
  material numbers; filler-word perfection is not required.
- [ ] Memo/deck, visible output, transcripts, and validation record do not conflict.
- [ ] No password, key, token, credential, private data, or `.env` is committed/submitted.
- [ ] Every recommendation includes condition, reversal trigger, and committee ask.
