# Starter Help Ladder — Learn Without Surrendering the Work

**First check the current task's AI Boundary Card.** During AI-closed work or before the required
Edition A receipt, stop at Level 2 and use the published human support route; Levels 3–4 are
available only when that task explicitly permits AI. This ladder never changes a task's AI rule.

Use the lowest level that gets you moving. Preserve your first error, prediction, and test result
so the help exchange produces evidence rather than a completed solution you cannot defend.

## Level 0 — Restate the contract

Write the required input, output, units, source, and one known failure condition. Save the first
error or surprising result exactly as it appeared.

## Level 1 — Make the expectation visible

Read the function docstring and data dictionary. Before changing code, write one prediction and
one tiny test. State what a correct value should look like and why.

## Level 2 — Reduce to a known-answer case

Replace the full dataset with two or three transparent observations. Calculate the expected
answer by hand, run the code, and identify the first point where the two paths diverge.

## Level 3 — Ask AI about one boundary

Share the smallest safe excerpt plus the error, expected behavior, and test. Ask for a diagnosis,
not a completed file or repository. Do not paste credentials, private data, licensed material, or
unreleased student work. Treat the response as a hypothesis and rerun the known-answer case.

## Level 4 — Request pseudocode, then own the implementation

If the diagnosis is still unclear, ask for pseudocode or two competing explanations. Implement
the change yourself, inspect the diff, and test both the known-answer case and one adverse case.
Record what the AI proposed, what you accepted or rejected, and why.

## Level 5 — Escalate with evidence

Bring the TA or instructor your contract, first error, prediction, minimal example, AI-use record,
and current result. Support may diagnose the next boundary or demonstrate a parallel example; it
will not supply a submission-ready solution.

## Stop conditions

Stop and escalate when a credential or private source may be exposed, the output could affect a
real financial decision, the source definition remains ambiguous, or you cannot explain the code
you are about to submit. A working output without an owned reasoning chain is not completion.
